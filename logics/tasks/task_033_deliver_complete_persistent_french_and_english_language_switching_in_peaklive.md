# Report
- Delivered in four waves. Wave 1 replaced the single-catalog `translate()` with a locale-aware service: full French/English catalogs at leaf-key and placeholder parity, deterministic English fallback that never raises inside a paint or signal handler, once-only missing-key diagnostics, and an application-scoped `ui-settings.json` read before the first widget exists so the language is independent of measurement profiles.
- Wave 2 added Setup > Language and in-place retranslation. Nothing is rebuilt: menu actions keep their identity, shortcuts and check state; combo entries are rewritten by stable item data so no index moves and no configuration mutation is issued; trees and tables are re-headed rather than repopulated, preserving selection, expansion and scroll.
- Wave 3 moved dynamic text to semantic keys with parameters, so a message already on screen re-renders in the new language, and localized the session report, anomaly counters and decode states while leaving every fact, identifier and machine-readable contract untouched. Externally supplied driver, OS and DBC text stays verbatim inside the translated message around it.
- Wave 4 added the coverage, the packaging and the documentation, and carried the language into Qt's own dialog chrome, which the catalog alone does not reach.
- Two defects were found by validation rather than by review. The Windows smoke run showed the stored preference ignored because PowerShell had written it with a UTF-8 byte-order mark; the recovery path behaved exactly as designed, but a BOM is ordinary on Windows, so the preference is now read with `utf-8-sig`. The packaged French build also named the synthetic lane two different ways in one window, because the measurement table took its title from the series key; one helper now answers that for both surfaces while the key itself stays ASCII English.
