# Validation
- Wave 1 (item_126) allocation policy: separated the single `_expanded_widths` store into a strict preferred-width cache that is only updated by an explicit operator action. `_remember_panel_widths(only=<panel>)` now scopes the capture to the one panel whose `collapsed_changed` signal actually fired (via `self.sender()`), never its siblings, and `_persist_layout()` no longer calls `_remember_panel_widths` at all — only `_splitter_dragged()` (wired to `QSplitter.splitterMoved`) and `_panel_collapse_changed()` do, each before any reflow runs. This stops two corruption paths: (a) `_persist_layout`'s old unconditional re-remember after `_reflow_workspace` had already applied an automatic equal-share split when the centre panel collapsed, and (b) a sibling panel's currently-allocated (not preferred) width being captured just because a different panel's collapse state changed, e.g. the sole remaining open side panel absorbing 100% of the released width and then having that absorbed value promoted to "preferred" when a third panel was reopened. `reflow_widths` itself (src/peaklive/ui/layout_reflow.py) is unchanged: hidden-panel concept is out of scope for Wave 1 (added in Wave 2/item_127); collapsed panels consume `RAIL_WIDTH`; open panels respect `MIN_SIDE_WIDTH`/`MIN_CENTER_WIDTH`; the centre absorbs released space.

- Wave 2 (item_127) design: visibility is a new explicit per-panel flag (`CollapsiblePanel._hidden`/`is_hidden`/`set_hidden`), independent of `is_collapsed`, so it satisfies AC1's "reflects explicit state rather than parent/window `isVisible()` timing" — `is_hidden` is never read back from `QWidget.isVisible()`. `set_hidden(True)` calls `QWidget.setVisible(False)` on the whole `CollapsiblePanel` (header, body, and rail together), which Qt's `QSplitter` treats as releasing that column and hiding its handle automatically (verified empirically: hiding a middle splitter child gives its neighbours the freed width and hides both adjoining handles, with no residual gutter). `reflow_widths` (src/peaklive/ui/layout_reflow.py) gained an optional `hidden: list[bool]` parameter: a hidden panel always gets width 0 (not `RAIL_WIDTH`) and is excluded from `open_indexes`, so a hidden centre panel is treated like a collapsed one for side allocation (sides equally share the released width) while a hidden side panel simply stops competing for space; the parameter defaults to all-`False`, so the existing positional-args call sites and the parametrised arithmetic test are unaffected. Persistence: `WorkspaceLayout.hidden_panels: list[str]` (src/peaklive/domain/models.py), additive and defaulting to `[]` (so every profile saved before this field existed restores with all panels visible), serialized/deserialized exactly like the existing `collapsed_panels` list. `_show_profile` (src/peaklive/ui/profile_controller.py) calls `panel.set_hidden(...)` before `panel.set_collapsed(...)` so a panel's collapsed/expanded state is preserved underneath a hide and reapplied unchanged on reveal (verified by `test_showing_a_hidden_expanded_panel_restores_its_remembered_width` and `test_showing_a_hidden_collapsed_panel_restores_the_rail_not_the_full_width`). `_persist_layout` writes `layout.hidden_panels` from `panel.is_hidden` on every persist call (unlike `panel_widths`, there is no "automatic redistribution" risk to guard against here, since hidden is only ever set by an explicit operator or profile-restore action). Three new checkable `QAction`s (`menu.view_signals`, `menu.view_graphs_trace`, `menu.view_inspector`, added to `logics/i18n` en.json and validated with `logics-manager i18n validate`) live in `src/peaklive/ui/actions.py`, keyed in `self._panel_visibility_actions` by panel key; each action's `toggled` signal drives `panel.set_hidden`, and each panel's `visibility_changed` signal drives the action's `setChecked`, so the menu checkmark and the panel state can never drift, including immediately after a profile switch (`_sync_visibility_actions` re-syncs all three defensively once restoration finishes). The View menu itself lives on `QMainWindow`'s menu bar, independent of the central splitter, so it — and every checkable action in it — stays reachable and triggerable even when all three panels are hidden, giving the all-hidden recovery path required by AC2 without any special-case code. `Ctrl+B` (`_toggle_signals_panel`, src/peaklive/ui/main_window.py) now reveals Signals first when it is hidden, then expands it, in the same keystroke, so the shortcut always leaves Signals both visible and usable.

- Wave 3 (item_128) design: the per-lane title moves from a `QLabel` in its own `QVBoxLayout` row above the `PlotWidget` to a `QLabel` overlay parented directly to the `PlotWidget` (`src/peaklive/ui/panels/graph_lane_header.py`), positioned by the new `anchor_lane_title()` rather than laid out — it therefore contributes no layout height and no autorange padding by construction (it is never added to any layout or scene item that autorange walks). Positioning reads `viewBox.sceneBoundingRect()` mapped into the plot's own widget coordinates (`plot.mapFromScene(...)`), which is the ViewBox's actual on-screen pixel rect; that rect is unaffected by pan/zoom (only the data-to-pixel mapping inside it changes), so the overlay stays anchored through those gestures without any per-frame repositioning. It is re-anchored on `ViewBox.sigResized`, which fires for both window/splitter resizes and axis-width layout changes (e.g. the Y-axis widening), and once eagerly in `build_lane` for the common case where the geometry is already valid. Title text is elided to `TITLE_OVERLAY_MAX_WIDTH_FRACTION` (60%) of the ViewBox width via `QFontMetrics.elidedText`, so a long or duplicate name never crowds the plot; the full identity remains exactly where it was (the header's own `toolTip()`/`accessibleName()`, set to `lane_identity()`'s `detail`), unaffected by elision of the visible text. `Qt.WA_TransparentForMouseEvents` plus `Qt.FocusPolicy.NoFocus` on the header let pan/wheel-zoom/fit/A-B-cursor-drag gestures started under the title pixel area fall through unchanged to the `PlotWidget`/`ViewBox` beneath it. The `lane` wrapper (`src/peaklive/ui/panels/graph_lane_header.py::build_lane`) now contains only the plot (no header row), so `LANE_SEPARATOR_STYLE`'s bottom-border separator (item_112 AC2) moves with it onto the plot's own immediate parent, unchanged in appearance. `lane_identity()`, curve-colour-in-tooltip matching, and the DBC-hash-in-tooltip-only contract from item_112/task_016 are all preserved untouched — only the title's placement changed, coordinated by touching no other part of task_016's delivery.
