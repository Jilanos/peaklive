- Wave 4 (2026-09-12): item_123, two scoped fixes to `GraphStackPanel`'s viewport request bookkeeping (the fuller scheduler/byte-budget/full-file-late-selection scope in item_123 remains open). (1) A cache hit for a new viewport used to leave any still-running worker for a previous viewport untouched and did not bump the request generation; a slow worker completing later would then pass the (unchanged) generation check and overwrite the cache-hit display with stale data — the "cache-hit A/B/A race" named in the diagnosis. The cache-hit path now bumps the generation and cancels the in-flight worker exactly like a cache miss does. (2) The completion handler cached its result under a key rebuilt from whatever viewport the UI showed at completion time rather than the viewport actually requested; if the operator kept navigating while a query was in flight, the result was filed under the wrong key, poisoning a later legitimate cache hit for the viewport it was really computed for. The request's own key is now threaded through `_history_request_keys` (keyed by generation, replaced rather than accumulated so it can't leak across an unbounded number of navigation gestures) and used at completion instead of recomputed state. New tests in `tests/test_graph_stack_history_scheduler.py`, both confirmed to fail without the fix. Full `uv run python -m pytest tests/` and `ruff check` are green. Still open in item_123: the byte-budget cache accounting audit, actual mid-query SQL/chunk cancellation, canonical revision-aware viewport keys, and the full-file late-selection background reconstruction (AC6) — none of these are touched by this wave.
- Wave 5 (2026-09-12): item_123, nonmodal worker-failure presentation. `HistoryViewportWorker.failed` was emitted but never connected to anything in `GraphStackPanel` — a background read failure (source missing/changed/permission error) was silently dropped, with only a log line the operator never sees. `refresh_data()` now connects `worker.failed` to `_historical_refresh_failed`, which shows a new nonmodal error message (`graph.history_error`, added to `src/peaklive/i18n/en.json`) on the existing `StateNote` (`self.note`) without touching the currently-displayed curves — the last valid view is retained rather than blanked, consistent with AC6's "retain last valid data" requirement. Full `uv run python -m pytest tests/` and `ruff check` are green. - Wave 6 (2026-09-12): item_123, cache-hit point-budget double counting. `_historical_refresh_completed` unconditionally added the result's point count to `_history_result_cache_points`, including on the cache-hit path in `refresh_data()`, which calls it directly with the already-cached payload.
